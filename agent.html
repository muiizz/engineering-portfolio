Did the agent pick the right tool?

A support agent with four tools, tested on 24 tasks in three languages. The score is about the tools it chose and when it stopped. Step through what the model actually did.

Across three runs, Haiku 5.5 passed 24, 23 and 24 of 24 tasks. Sonnet 5.5 and Opus 5.5 passed 23 of 24 in every run.

Evidence

  • Agent, tools, tasks and scorer
  • Recorded results
  • Every Opus transcript
  • Every Sonnet transcript
  • Every Haiku transcript

Scope

  • Mock backend, two bookings, two help articles
  • One provider, three runs per model
  • 24 November 2026

The setup

The model can look up a booking, search the help articles, hand off to a person, or raise an urgent case. The rules are short: look a booking up before talking about it; refunds are looked up and then handed off; danger is raised at once with no other tool; an unknown booking is not a reason to hand off; and some messages need no tool at all.

What is scored

Each task states the tools that must be called and in what order, the tools that must not be called, the booking code that must be passed, and a fact the final reply must contain. A task passes only if all five checks pass. A scripted agent that always hands off scores 0 of 24, which shows the scorer can fail a wrong choice.

Every model chose the right first tool on every task, passed the right booking code, raised all three safety reports as urgent without touching another tool, and never handed off an unknown booking.

The one failure is my task, not the model

The two larger models failed the same task in all three runs. Asked “When do I check in for B-1002?”, they looked the booking up, found the date, and then searched the help articles for a check-in time of day. The scorer expected one tool call and marked the second as a failure. The question is ambiguous, the extra search was reasonable, and the reply said plainly that it could not find a time. The smallest model answered with the date alone and passed. Its own single failure, in one run, was searching the help articles twice for the desk hours in Urdu.

That is a useful result about the test. An exact-sequence check punishes a model for being thorough. The next version should score required calls and forbidden calls separately, and count extra harmless calls as cost, not as failure.

What this does not show

Eight task types with a tiny mock backend is a small test. Nothing here measures long conversations, tools that fail or time out, or a customer who changes their mind. I wrote the tasks, the tool descriptions and the scorer, and a native Urdu reader has not reviewed the messages.
