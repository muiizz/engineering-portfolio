Applied AI, clinical safety

Rules decide before the model does

Divia is a doctor-led coaching programme for people with diabetes and prediabetes in Pakistan. Patients talk to an AI coach on WhatsApp under physician oversight. I founded it and designed its safety architecture.

The decision

A language model could not be the only thing standing between a patient and harm. A deterministic rules engine runs before the model and decides thresholds, emergency words, double-dose detection and urgent routing. The model is the second safety net, never the first.

Testing at the boundary

Every threshold is tested just below, at and just above its value, in both mg/dL and mmol/L. The rules engine is held at 100% branch coverage, with scheduled mutation testing, and each test is traced to an entry in a hazard log.

In the campaign of 23 October 2026 the tests killed 1,427 of 1,497 mutants of the rules engine, 95.3%. The scheduled job fails below 90%. An earlier campaign, before targeted tests were added, scored 81.5%.

Reading a meter from a photo

Glucose readings are taken from photos of the patient’s meter. Two independent reads must agree before a value is accepted, and a plausible low value is escalated as urgent at once.

Evaluating the coach

An automated evaluation runner checks the coach’s behaviour against a clinical test workbook, which is the source of truth for expected behaviour. Every reply is checked by code for its tag, for never tagging below the rules engine, for the required urgent steps word for word, for medicine advice, for script and language, and for style. People score only what code cannot judge, such as tone and cultural fit.

Live evaluation, 24 November 2026

I ran the full Pakistan test workbook through the real coach service: the rules engine first, then the production model, then the output checks. The run was complete and the runner’s verdict was OK.

87 cases, up to three runs each, 211 replies in total
Replies passing every automatic check206 of 211
Urgent cases passing every check, all three runs22 of 22
Failures on a safety check0
Model calls155, with 10 retries and none failed
Cost$1.72

All five failures were the same check: the coach escalated to the doctor where the workbook expected an ordinary reply. That is more cautious than the workbook, and it is a cost, because every needless escalation takes a doctor’s time. None were in Urdu script; they were in English, Roman Urdu and mixed messages.

In two replies the model failed the output checks twice, so the system sent the approved fallback message instead. Those count as passes, because the fallback is the designed behaviour when the model cannot be trusted.

The prompt cache carried 154 of the 155 calls. Without it the run would have cost about $8.17. The runner does not record tokens or per-call latency, so I am not reporting them. This run used the standard workbook, not the larger signed release set, so it is not a release verdict.

Clinical governance

All clinical content and thresholds are versioned and approved by the Chief Medical Officer. Every outbound message records the content versions and the model used.

Data protection

The model receives a patient code, never a name or phone number. Row-level security applies to every patient table. Health data is exchanged as HL7 FHIR R4 with LOINC and SNOMED CT codes.

What this page does not show

Divia’s repository is private, so nothing here can be reproduced from this site. The demo above is a small illustration of the order of checks, with one widely used threshold. The measured, reproducible work is in the open-source rules engine linked under Related.
