Engineering practice

Ten things that broke

Each report says what happened, why, what fixed it and how the fix was checked. Three of them are from the evaluations on this site, including one where my own harness produced the wrong result.

Evidence

  • Full reports with commands

Scope

  • Synthetic fixtures and disposable environments
  • No production records
1A multilingual message missed the review queue
Impact
The baseline missed seven of ten review-worthy fixtures.
Root cause
Three English phrases did not cover Roman Urdu and Urdu wording.
Fix and verification
Six translated phrases and normalised punctuation and Urdu characters. Missed reviews fell from seven to one, with one false alert when a matched phrase was followed by a denial.
2A TypeScript error passed the commit hook
Impact
An invalid type assignment was committed in a disposable repository.
Root cause
The fast commit hook checks secrets and Python only. Full compilation happens at the push gate and in CI.
Fix and verification
Type checking stays in both the push gate and CI, so a local bypass does not remove the server-side check. The faulty push exited 1 at TypeScript.
3Mutation artifacts interfered with test discovery
Impact
pytest discovered both the real tests and copies emitted by the mutation tool.
Root cause
Test discovery started at the repository root and included the mutation work directory.
Fix and verification
Discovery is scoped to the tests directory, and the ordinary gate is rerun after a mutation run.
4A selective query scanned a million rows
Impact
A weekly dashboard query returning 96 rows took a median of 67.169 ms.
Root cause
The primary key did not serve the tenant and date filters.
Fix and verification
A composite index on tenant and date. The median fell to 0.126 ms and both ordered exports matched byte for byte.
5Delivery was accepted before the worker recorded it
Impact
A provider accepted a delivery, then the worker failed before marking it sent, and the next worker tried again.
Root cause
The provider and the local database have separate commit boundaries. A local lock cannot make both commits atomic.
Fix and verification
Retry with the same event ID, which the provider uses as a unique key. The test asserts one delivery and no duplicate.
6A section name pointed to the wrong destination
Impact
The same display name meant position two one year and position one the next, so a name match would move a student to the wrong section.
Root cause
A display label is editable and is not an identity.
Fix and verification
Select by grade, year and stable position, with a uniqueness constraint on those three.
7Automation toggled repeatedly near its threshold
Impact
A reading alternating between 49 and 51 requested 11 switches in 12 samples against a single threshold of 50.
Root cause
One switching threshold turned ordinary variation into repeated state changes.
Fix and verification
A deadband: on at 55 and above, off at 45 and below, and a command only on transition. An offline replay produced zero transitions.
8Replies were cut off and scored as model failures
Impact
The first live model run reported 68 of 120 for the smallest model. The figures were wrong.
Root cause
The harness capped replies at 200 output tokens. Urdu script uses several tokens per word, so Urdu replies stopped mid-sentence and failed to parse.
Fix and verification
The cap is 1,000, and every run records its stop reasons and a truncated count. The rerun scored 116, 118 and 120.
9The scorer failed a correct refusal
Impact
Two replies failed in each run although they had the right route and declined to promise a refund.
Root cause
The scorer banned the phrase “guaranteed refund” wherever it appeared.
Fix and verification
It now looks for a negating word near the phrase. Rescoring moved that model from 118 to 120. It is still a heuristic.
10An ambiguous task failed two models for being thorough
Impact
The two larger models failed the same agent task in all three runs.
Root cause
Asked when a guest checks in, they found the date and then searched for a time of day. The task was ambiguous and the scorer required exactly one tool call.
Fix and verification
Not yet applied: score required and forbidden calls separately, and count extra harmless calls as cost. The result is published as recorded.

What they have in common

Most of these were caught by a check that existed for another reason: a unit test, a byte-for-byte comparison, a count of truncated replies added after the fact. The last three were found by reading the failures instead of trusting the score.
