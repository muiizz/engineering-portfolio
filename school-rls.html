PostgreSQL, access control

Who can see which applicant

Sign in as each school role. The rows you cannot read are still there; the database is the one refusing to show them.

Campus principals read and admit their own applicants. Head office reads all and can read the audit. Teachers, accountants, parents and unlinked accounts see no applicant rows.

Evidence

  • Lab notes and SQL
  • Supabase policies
  • Verification SQL

Scope

  • Invented campuses and sections
  • Verified on PostgreSQL 16.2

The rule

Two campus staff roles can read their own applicants. Direct table writes are withheld. A security-definer admission function checks campus and current state before it updates a row.

A successful admission and its audit record commit together. Rejected and repeated calls create no audit record.

Promotion

The promotion fixture intentionally reuses a section name at a different position next year. It checks that a student follows the section position even when the destination has a different name.

What this leaves open
