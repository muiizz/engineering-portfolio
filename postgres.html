Finding 96 rows in a million

A school attendance dashboard filters by school and week. I generated one million fictional records, then ran the same ordered query before and after adding an index on (tenant_id, attended_on).

67.169 ms to 0.126 ms

These are median execution times over five measured runs per condition, after one warm-up each. Both queries returned the same 96 records in the same order. PostgreSQL could use the new index to locate the matching range.
