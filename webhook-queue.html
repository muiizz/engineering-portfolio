PostgreSQL, background jobs

A webhook queue that survives replays

Send events, replay one, break one. The queue below follows the same rules as the PostgreSQL version: one row per event, one worker per row, five attempts.

A unique event ID makes replay a no-op. Workers lock one row each and skip rows held by others. Invalid payloads reach the dead-letter table after five failures.

Scope

  • PostgreSQL 16.2, local synthetic provider

Intake

Intake authenticates the timestamp and raw body before inserting a job. A unique event ID makes replay a no-op. The receiver returns 202 after the transaction commits, including for duplicates.

Workers

The worker locks one available row and skips rows held by other workers. The outbox insert and job completion commit together. A database rollback releases an interrupted claim. Invalid payloads back off and reach the dead-letter table after five failures.

What was verified

Against PostgreSQL 16.2, the verification script passed replay deduplication, recovery from an interruption after the synthetic provider accepted delivery, concurrent claims over 100 events with eight workers, and dead lettering after five failed attempts.
