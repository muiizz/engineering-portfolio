The problem

A change can look complete while a required check has failed or never ran. This fictional release gate models a simple policy for deciding whether a set of required checks is ready.

The approach

The gate requires each named check to be present and exactly marked pass. Missing and failing checks are returned as actionable issues. The tests exercise a passing release, a failure, and a missing check. CI runs the same tests on pushes and pull requests.

python -m unittest discover -s tests -v
python demo/quality_gate.py

What to look for

The example keeps policy separate from presentation, makes missing evidence visible, and returns a nonzero exit code when a release is blocked. It is intentionally small, so it can be inspected and changed quickly.

Scope

This is a synthetic contract demonstration. It does not connect to a deployment system or establish that a real release is safe.
